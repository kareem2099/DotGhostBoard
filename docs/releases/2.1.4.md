# DotGhostBoard v2.1.4 — Keep capturing when Dashboard locks

Dashboard locking now hides private UI without interrupting ordinary local clipboard
history after your first successful login. The Vault stays locked, its decryption key
is cleared, and its process-local recognition index continues excluding known secrets.

## What's fixed

- Manual and idle Dashboard locks no longer stop protected local capture or open a
  modal password prompt. Open the app when ready to authenticate again.
- Pause/Resume remains an explicit control, including in the locked tray menu. The
  tooltip distinguishes active capture, pause, and waiting for first authentication.
- Captures made while locked appear after unlocking; hidden history widgets and secret
  prompts are not populated by new captures while locked. API and LAN sync remain stopped.
- Vault and CSV password matches stay out of Dashboard history. If recognition cannot
  verify text, it is excluded. New suspected secrets are excluded while locked; unlock
  and copy again to review them. Notification preferences remain respected.
- Vault protection handlers are installed before starting clipboard capture.

Cold startup still requires initial authentication, including the independent Vault
password when enabled. Locking does not encrypt ordinary Dashboard history on disk.
Dashboard auto-lock remains disabled by default; the Vault retains its separate timer.

## Downloads

Linux x86_64 builds: DEB, AppImage, portable tarball, and Arch package, with SHA-256
checksums and detached OpenPGP signatures.

### Build compatibility

These binaries were built on Kali Rolling 2026.3. A bundled library requires
`GLIBC_2.43`; older Debian/Ubuntu systems can fail to start these builds. The AppImage
uses the same compiled runtime and does not remove that requirement. Broader support
for older distributions is deferred to a separately rebuilt and tested release.

### Validation

The full local suite passed **709 tests in 443.45 seconds**, including 15 regressions
for locked capture, password exclusion, Pause/Resume, first authentication, independent
Vault reauthentication, tray state, and the actual Qt clipboard timer.
The extracted DEB executable and AppImage also started with isolated fresh profiles;
their resulting SQLite databases passed integrity checks. These were smoke checks,
not installation tests across other distributions.
