# DotGhostBoard 2.1.3 release preparation

Prepared locally on 20 October 2026. Nothing in this checklist publishes a release.
The existing 2.1.2 release and its checksums are preserved.

## Release scope

The exact source paths for this release are listed in [2.1.3-files.txt](2.1.3-files.txt).
This includes the Vault security and recovery work and its UI, tests, and documentation.
It excludes these pre-existing local changes, which remain untouched:

- `roadmap(v2.x).md`
- `ROADMAP_2.2.0.md`
- `dotshare-devto.md`
- `scripts/run_i3_sim.sh`

No files have been staged or committed as part of preparation. When ready, use the
explicit manifest instead of `git add .`, then inspect the staged diff:

```sh
git add --pathspec-from-file=docs/releases/2.1.3-files.txt
git diff --cached --check
git diff --cached --stat
```

## Version and UI

- Runtime config, Python project metadata, CITATION, README badge, AppStream metadata,
  and generated package metadata use 2.1.3. Historical release entries remain unchanged.
- Download instructions identify the 2.1.3 assets and explain that the links become
  available when the release is published; no follow-up README edit is required.
- Recovery selection supports case-insensitive search and bulk selection of visible
  matches, preserving choices hidden by a search. Auto Sync still includes future items.
- Setup, manual copying, verification, and restoration use background workers and
  modal progress. Duplicate actions and closing during an operation are blocked.
  Idle/recovery timers are coordinated and elapsed idle time is deducted on resume.
- A manual lock during backup password derivation leaves the previous configuration
  intact. Password fields are cleared on completion or cancellation.

## Validation

The final full suite passed **694 tests** with no failures or skips in **335.61
seconds**. This includes 36 recovery regressions and four recovery UI polish tests.
The final run used isolated profiles, offscreen Qt, loopback API tests, and temporary
Openbox/Qtile displays. `git diff --check` also passed.

The release binary was built with PyInstaller. Four local artifacts were generated:
DEB, portable tarball, Arch package, and AppImage. Their SHA-256 values are recorded
in [2.1.3.sha256](2.1.3.sha256); validate them from the repository root with:

```sh
sha256sum -c docs/releases/2.1.3.sha256
```

Package smoke checks use synthetic data under a temporary directory and an isolated
X11 display, without opening the user's real profile:

- Fresh profile: the compiled application opens Dashboard and Settings successfully.
- Upgrade: the extracted DEB binary opens a schema-1 fixture with the legacy key
  envelope, migrates its record and history to authenticated encrypted schema 2,
  and preserves the expected secret, title, category, and history value.
- Recovery: the final extracted DEB verifies an encrypted archive in the actual UI,
  restores it into a new profile, writes fresh credentials, and preserves the source.
  The restored secret and title were independently verified afterwards.
- The final AppImage starts successfully with `APPIMAGE_EXTRACT_AND_RUN=1` and
  creates a fresh temporary profile.
- Settings and both recovery destination layouts were visually inspected on X11.

These checks exercise extracted packages, not a system-wide package-manager install.
Arch and tarball checks cover packaging and contents; no separate Arch host was used.
The local build products are not signed or published by this preparation step.
