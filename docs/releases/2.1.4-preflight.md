# DotGhostBoard 2.1.4 validation and release scope

Validated on 21 October 2026. This hotfix separates Dashboard access from protected
background capture. Compatibility rebuilding for older systems is deferred.

## Regression validation

- Full suite: **709 passed in 443.45 seconds**, with no failures or skips in that run.
- Fifteen locked-capture regressions include manual/idle lock, normal/PRIMARY input,
  shared/independent Vault passwords, CSV passwords, first authentication, explicit
  Pause/Resume, stale recognition checks, startup ordering, and the real Qt clipboard timer.
- Warm independent reauthentication remains locked until both password steps succeed.
- Session/Vault decryption buffers are cleared; known values never enter history and
  captured text does not reach outbound LAN sync while locked.
- Git whitespace checks pass. Runtime, project, citation, README, and AppStream metadata
  identify 2.1.4; historical release documentation remains unchanged.

## Package validation

- Built DEB, AppImage, Arch package, and portable tarball from the compiled runtime.
- The extracted DEB contains version 2.1.4 and the new capture controller.
- Extracted DEB and AppImage started with isolated fresh profiles; both generated
  readable SQLite databases with `PRAGMA integrity_check` returning `ok`.
- The DEB process exited normally. The AppImage extraction wrapper was terminated
  by the smoke harness after startup; this is not a claim of a normal wrapper exit.
- Package hashes are recorded in [2.1.4.sha256](2.1.4.sha256).
- The four packages and SHA256SUMS have detached OpenPGP signatures, verified locally
  with fingerprint `48E2D66B9B738A1D24DE5B2FD3EB5327471C8F22`.

These binaries were built on Kali Rolling 2026.3 and include a library requiring
`GLIBC_2.43`. Older Debian/Ubuntu compatibility is not established. AppImage uses the
same runtime. Arch packaging was inspected without testing on a separate Arch host.

## Scope

The explicit source manifest is [2.1.4-files.txt](2.1.4-files.txt). It includes the
previously prepared security-policy and inert GitHub-settings documentation. Pushing
those JSON files does not apply repository settings; there is no auto-apply workflow.

Pre-existing roadmap changes, ROADMAP_2.2.0.md, dotshare-devto.md, and
scripts/run_i3_sim.sh are excluded. Local articles and generated build outputs are
not part of the source commit. Build assets are uploaded separately to the release.
